V-Run · App Flow & Architecture

V-Run is a free web app that turns walking into a game. It syncs daily steps from Google Fit, or from a built-in sample month when Google Fit isn’t available. On top of those steps it runs 10K-a-day streaks, a plant that grows as you walk, 60-day team contests, individual and team rankings, and a streak-based reward chart.

⚠️ Google Fit status (researched Oct 2026)

  • Google stopped accepting new Google Fit API sign-ups on 1 May 2024 and is retiring the Fit APIs during 2026. No exact shutdown day has been published.
  • V-Run still includes the complete OAuth + REST integration. If you have existing Fitness API access, add the credentials to server/.env and it works.
  • Without credentials, or if Google errors, V-Run falls back to the sample month automatically, so the app never breaks.
  • Planned migration paths: Health Connect (Android, on-device) or the Google Health API. Only server/src/services/googleFit.js needs replacing; everything else reads from daily_steps.

Team rules

  • Maximum 10 members
  • One team per walker per contest
  • Joining is transactional (SELECT … FOR UPDATE) so teams can’t overfill

Leaving

  • If the captain leaves, the earliest remaining member becomes captain
  • When the last member leaves, the team is deleted
  • Leaving a contest also leaves your team

Lifecycle

  • Upcoming: start date is in the future
  • Active: day N of 60
  • Finished: read-only standings

5 · Game rules

🔥 Streak

  • Consecutive days at or above your goal (default 10,000)
  • Today doesn’t break the streak while the day is still in progress
  • The longest streak is tracked separately

🌱 Plant

  • Six stages: seed → sprout → seedling → sapling → young tree → bloom
  • A new stage roughly every 25% of the goal
  • Each goal day adds a tree to the 30-day garden

🪙 V-Coins

  • 1 coin per 1,000 steps (max 25 a day)
  • +10 for each goal day
  • Milestone bonuses: 3d +30, 7d +75, 14d +150, 21d +250, 30d +400, 45d +600, 60d +1000

🏅 Badges

  • Single day: 10K, 15K, 20K
  • Lifetime: 100K, 250K, 500K, 1M
  • Everything is free; there’s no paywall

External · optional

Google OAuth 2.0

Auth-code flow with offline access. A signed, 10-minute state JWT links the callback to the user and blocks CSRF.

Built-in

Fallback JSON

server/data/fallback-steps.json keeps the app working whenever Google is unavailable.

Security

  • bcrypt password hashes (cost 10)
  • Every SQL query is parameterised
  • Rate limits on auth and sync
  • Helmet headers; CORS limited to CLIENT_URL
  • Production refuses to start without a strong JWT_SECRET

Reliability

  • Automatic fallback when Google fails
  • Transactions for team changes
  • Health check at /api/health
  • Graceful shutdown that closes the DB pool

Folder layout

  • client/: React app (pages, components, context)
  • server/src/routes: HTTP layer
  • server/src/services: business logic
  • server/data: fallback month

9 · Run & deploy

Local development

  • npm run install:all
  • Edit server/.env (MySQL credentials)
  • npm run seed (optional demo walkers and teams)
  • npm run dev → web on :5173, API on :5050

Production (single process)

  • npm run build (outputs client/dist)
  • Set NODE_ENV=production, a strong JWT_SECRET, CLIENT_URL = public URL
  • npm start: Express serves the API and the SPA on one port
  • Put it behind HTTPS (nginx, Caddy, or a PaaS)
